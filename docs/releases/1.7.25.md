## 这一版解决什么

第三种运行形态被正式记录：**ACP 客户端（T3 Code 等）通过 `dsh --profile acp` 拉起宿主**。

这一形态最容易踩的坑是"半套生效"——宿主补丁是全局的（同一个 `Resources/app` 树），但提示词注入是 **profile 级插件**。空 `acp` profile 里宿主补丁生效但人设没换、`probe` 不回显，而界面上一切正常、没有任何报错。本版把这条链路、验收方法和后续维护点写进文档，并用测试钉住，避免下一个人按桌面版经验去接 ACP。

本版**不含宿主补丁变更**：仍然是 1.7.24 的 74 条补丁，补丁 ID 与锚点定义不变，桌面版无需重新「应用」。

## 升级注意

- 桌面版 / web profile：**不需要**重新「应用」，也不需要重启 DSH。
- ACP profile 是新装插件，命令固定为：
  ```sh
  dsh plugin --profile acp add \
    https://github.com/atompilot/dsh-purge/releases/download/v1.7.25/dsh-purge-community-1.7.25.tgz
  ```
  装完确认 `dsh.profile.bundles` 含 `dsh-purge-community`，再把 `dsh-purge-redteam-ui` 在该 profile 的 `cordis.patch.yml` 里 `disabled: true`。
- DSH 桌面更新后 `app.asar` 会回归，launcher 优先 asar，ACP 侧会**静默**变回未打补丁。顺序固定为 `dsh-purge-align` → 重开 ACP 客户端会话。

## 已知限制

- 其它 ACP 客户端（Zed 等）未实测；Windows 上的 ACP 接入未实测。
- ACP 下 ACP 交互式审批 / 等待回答语义未验证；面板与演练台 HTTP 桥不适用（无 `webServer`），不做兼容承诺。
- `selfcheck` 只覆盖宿主与当前 profile，不覆盖 `acp` profile；ACP 侧验收必须用"启动自检 + probe 回显"两条独立证据。
